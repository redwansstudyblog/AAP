# AAP Control Panel

এটা আপনার টিমের **নিজের সার্ভার** — কোনো ক্লায়েন্ট সাইটে এটা বসানো হবে না। এখান থেকে আপনি দেখবেন কোন কোন সাইট আপনার AI Access Protocol middleware ব্যবহার করছে, কতবার ব্যবহার হচ্ছে, আর দরকারে কোনো সাইটকে ব্লক বা নতুন ভার্সনে বাধ্য করতে পারবেন।

## এটা কী করে

1. **সাইট রেজিস্ট্রেশন** — যে সাইটে Package 1 (aap-site-setup) বসানো আছে, সেটাকে এখানে রেজিস্টার করলে একটা আলাদা `siteKey` পাওয়া যায় (এটা AI-কে দেওয়া AAP key থেকে সম্পূর্ণ আলাদা — এটা শুধু সাইট-থেকে-control-panel যোগাযোগের জন্য)
2. **Usage tracking** — প্রতিবার কোনো AI সেই সাইটে একটা AAP key redeem করলে (অর্থাৎ "ঢোকে"), সেই সাইটের middleware এখানে একটা লগ পাঠায়। ড্যাশবোর্ডে দেখা যায় কোন সাইট কতবার অ্যাক্সেস হয়েছে, শেষ কবে
3. **Block করা** — ড্যাশবোর্ড থেকে এক ক্লিকে যেকোনো রেজিস্টার্ড সাইটের AI access বন্ধ করে দেওয়া যায় (সেই সাইটের middleware নিজেই চেক করে এটা মেনে চলে)
4. **Release ম্যানেজমেন্ট** — নতুন ভার্সন পাবলিশ করলে (version নম্বর + changelog + ঐচ্ছিক "minimum required version"), প্রতিটা সাইট পরের version-check কলে এটা জানতে পারে এবং তাদের নিজের অ্যাডমিন প্যানেলে একটা নোটিফিকেশন ব্যানার দেখায়

## রান করা

```bash
npm install
ADMIN_TOKEN="একটা-লম্বা-র‍্যান্ডম-স্ট্রিং-বসান" PORT=4000 npm start
```

তারপর ব্রাউজারে `http://localhost:4000` খুলুন, `ADMIN_TOKEN`-টা পেস্ট করুন — ড্যাশবোর্ড খুলে যাবে।

## প্রোডাকশনে ডিপ্লয় করা
এটা যেকোনো Node.js hosting-এ (Railway, Render, Fly.io, নিজের VPS, এমনকি Vercel-এও একটা serverless adapter দিয়ে) ডিপ্লয় করা যায়। `ADMIN_TOKEN` env variable অবশ্যই production-এ সেট করতে হবে।

## গুরুত্বপূর্ণ সীমাবদ্ধতা — সৎভাবে বলে রাখা দরকার

- **এটা "silent remote code update" না।** কোনো সাইটের আসল কোড (middleware) এই সার্ভার থেকে দূর থেকে বদলে দেওয়া হয় না — এটা নিরাপত্তার কারণে ইচ্ছাকৃতভাবে বাদ দেওয়া হয়েছে (remote code execution একটা বড় supply-chain-attack ঝুঁকি)। এর বদলে: নতুন ভার্সন পাবলিশ হলে সাইটের অ্যাডমিন প্যানেলে নোটিফিকেশন যায়, আর সাইটের ডেভেলপার/টিম সেটা pull/deploy করে — এই একটা ধাপ প্রফেশনাল সফটওয়্যার ডিস্ট্রিবিউশনের স্ট্যান্ডার্ড প্র্যাকটিস (যেমন ব্রাউজার এক্সটেনশন, VS Code এক্সটেনশন, বা যেকোনো প্লাগিন ইকোসিস্টেম একইভাবে কাজ করে)।
- **"Force update" মানে কোড নিজে বদলে যাওয়া না, বরং অ্যাক্সেস বন্ধ করে দেওয়া** — `minVersion` সেট করলে, যেসব সাইট তার নিচের ভার্সনে আছে, তাদের AI-access endpoint (`/api/ai-access/session`) `426 Upgrade Required` রিটার্ন করবে, যতক্ষণ না তারা আসলেই আপডেট করে।
- **এই সার্ভার ডাউন থাকলেও কোনো ক্লায়েন্ট সাইট ভাঙবে না** — `telemetry.js` (Package 1-এ) সবসময় "fail open" — control server-এ পৌঁছাতে না পারলে চুপচাপ স্বাভাবিকভাবে কাজ চালিয়ে যায়।
- **`ADMIN_TOKEN` একটা একক শেয়ার করা পাসওয়ার্ডের মতো** — এই ভার্সনটা একটা ছোট অভ্যন্তরীণ টিমের জন্য ঠিক আছে। একাধিক মানুষ/রোল আলাদা পারমিশনে অ্যাক্সেস দেওয়ার দরকার হলে, একটা আসল auth সিস্টেম (NextAuth, Clerk, ইত্যাদি) দিয়ে এটা প্রতিস্থাপন করা উচিত।

## পরের ধাপ, যদি বড় করতে চান
- `server/db.js`-এর in-memory স্টোর একটা আসল ডেটাবেজ দিয়ে বদলান (Postgres সবচেয়ে সহজ পছন্দ)
- `ADMIN_TOKEN`-এর বদলে real multi-user auth
- নতুন রিলিজ পাবলিশ করলে ড্যাশবোর্ড থেকেই একটা "notify all sites now" পুশ (বর্তমানে প্রতিটা সাইট নিজে থেকে periodically চেক করে, push না)
